## 1. 产品定位与架构基线

### 1.1 定位

- **纯 B2B**：面向住宅零售商、商业工程经销商、FF&E 项目方；不做 C 端 DTC。
- **对客品牌＝Madehall**（Fabbrio 为已废止旧名）。域名、水印、报价单抬头、邮件署名均用 Madehall。
- **界面语言**：客户面全英文（EN 版随中文定稿后统一出）；内部后台中英双语。

### 1.2 系统架构

- **双系统分工**：
  - **Shopify Advanced**＝交易真值：账户、Company、Catalog、Price List、Draft Order、Order、收款、履约。
  - **自研 FF-DB**＝配置、RFQ、报价、CAD、状态机、商户审核、审计。
- **技术与安全契约**：
  - 前端零特权凭据；文件私有对象存储＋短期签名 URL；CAD 下载按 company_id 鉴权。
  - Shopify metafield 统一 `ff_custom.*` 命名空间；Webhook 幂等与对账。
  - 全部状态流转走后端白名单＋AuditLog；报价金额＝Σ line_price 逐行卷积单一算法。
  - Tier2/3 结账必须走 Draft Order（必要时锁价 custom line item）。
- **跨域登录**：Customer Accounts OAuth/PKCE＋BFF＋Customer Account API（已验证）；Draft Order 写入与锁价 payload 的真实闭环待 BE spike 补证（技术验证项 Q004）。
- **AI 全面废止**：拆单、brief、工厂匹配及一切 LLM 依赖下线冻结。

### 1.3 产品模型

- **三档产品**：Tier1 现货／Tier2 半定制／Tier3 全定制。
- 每个产品有**可售档位集合**（{T1,T2,T3} 非空子集），由能力数据**自动派生、无人维护**：
  - 含 T1＝有备货变体（Shopify 在售）；
  - 含 T2＝有参考变体（metafield 标身份）；
  - 含 T3＝品类有取材表模板。
  - 缺项＝显式故障，不得静默放行。
- **PricingRule 仅承载**：①历史 Quote 版本锁定快照；②满额阶梯折扣。Tier2 参考价场景已退出（改参考变体人工预录）。

### 1.4 币种与付款

- **币种**：报价/成交默认 USD；多币种记录与汇率快照随版本存档（CNY→USD 换算凭据）。
- **付款计划（不提供信用账期，Net terms 恒为零）**：
  - Tier1 现货：一次性全额；
  - Tier2/Tier3：30% 定金＋70% 发货前付清；
  - 项目单：按档分别计收——**首期＝现货行全额＋半定制行 30%；尾期＝半定制行 70%**。
- **收款载体统一 Shopify**：首期/尾款/补收三类同走 Draft Order 自定义行项；**不得建"尾款"类真实产品**；独立成单不回填原 Quote；对账 1:N＝Quote 总额=名下全部 Draft Order 之和；金额系统算、人工核对建单。

## 2. 角色与权限

- **六业务角色**：产品设计工程师／项目经理／商务运营／报价与供应链协调员／客服专员／财务只读。
- **root**＝负责人总控账号：九区全可见全可执行；四眼不豁免；AuditLog 记 root 不冒名。
- **四眼原则（maker≠checker）**：
  - 单据级报价复核：**项目经理仅复核项目单报价；散单报价复核＝商务运营**（按业务线切分，谁负责谁复核）。
  - 主数据级发布：仅商务运营；root 可代发（四眼仍生效，须另一人复核）；**若在岗者仅 root 一人，主数据发布卡住不放行**，不得单人闭环。
  - 设计成果发布同受四眼约束；涉钱涉权限一律不豁免。
  - 人工代录只替代"谁操作"，不替代"谁复核"。
- **权限实现**：后台登录强制；隔离双层＝后端白名单 403（安全真值）＋UI 按角色显隐；15 既有权限点迁移矩阵随迁移批，新增动作点随实施批定义。
- **角色×区可见性（仅 UI 显隐层，动作级授权以九区表＋后端白名单为准）**：
  | 角色 | 可见区 |
  |---|---|
  | 客服专员 | 区1/2/6 |
  | 商务运营 | 区2/4/5/6/9 |
  | 产品设计工程师 | 区3 |
  | 项目经理 | 区5/7（区7 属第二批，首批实际仅区5） |
  | 报价与供应链协调员 | 区5/6 |
  | 财务只读 | 区8 |
  | root | 九区全部＋系统管理面（zsys） |

## 3. 商户准入

### 3.1 开通与审核

- **全自动开通**：客服审核通过＝准入决定→后端全链自动开通（Company＋Location＋Customer 绑定＋Catalog/Price List 分配＋激活邮件）；失败进异常队列（断点重试/人工代建＋回填 GID）；全程幂等；不暴露半开通态。
- **不设批发等级**：统一分配同一 Catalog/Price List（取消的是"分档"，不是"分配"；登录见批发价靠分配承载）。
- **审核**：客服单层（通过/退回补件/拒绝＋备注）；拒后可重提，无黑名单。
- **状态**：准入七态（submitted/provisioning/provision_failed/need_info/rejected/active/suspended）＋对客五档映射；查看渠道＝魔法链接状态页（30 天时效）。
- **审核中时效展示**：展示弱承诺（"通常 N 个工作日内完成审核"形态，N＝🟡⑯），不给具体截止时点。
- **退回补件**：MVP 指出项为自由文本（客服备注）；补件页开放全部字段、客服备注高亮展示；字段级结构化指出项挂 V2。补件三增强＝附言框／拍照上传／客服代传。
- **客服代传补件**：入档＝自动 `need_info→submitted` 重新入队（与自助补件同边）；AuditLog 记「客服代传」＋实际执行人；代传客服可继续审核该单，但代传人与审核人须双留痕。

### 3.2 登录门控

- **非 active 一律等同未登录态**：审核中/需补材料/未通过三档本就无账号（Customer 绑定发生在转 active 时），查看状态/补材料走魔法链接免登录令牌。
- **suspended 禁止登录**：登录时即拦截，显示「账户已停用。如有问题，请联系客服」；不做"登录后只读"形态。
- suspended 对客文案统一为上述措辞；英文措辞归契约定稿文案基线。

### 3.3 停用与恢复

- 停用/恢复由商务运营执行；Shopify 侧联动停购/恢复；在途单默认 on_hold。
- **停用前置检查**：执行停用前系统检查该商户有无在途单/在设计单；有则弹窗列出受影响**单据号＋当前状态**，操作人员可强行停用（软拦截）。强停后在途单落 on_hold＋进人工处置清单；弹窗与强停决定全程 AuditLog。
  - **在途判定范围**（判据＝我方或客户已有实质投入）：①已接受报价未付定金（deposit_pending）；②已付款未收货（deposit_paid 起至 delivered＋尾款结清前）；③在设计（`in_design` 及设计资产未交付）。未接受的询价/报价不计入。

### 3.4 其他

- **商户详情面**：资料 12 项可编辑＋申请轮次历史＋时间线三合一。
- **状态命名空间通则（跨域适用）**：状态名各域独立，不因跨域撞名改名；跨域引用必须带域限定（如 `准入.submitted` / `RFQ.submitted`）；呈现上分表不合表。
- **root 账号管理＝五动作**：建号／停用／恢复／重置密码／角色分配，全程 AuditLog。边界：root 不能恢复 root（root 自身停用/恢复走脚本＋SOP）；恢复后角色分配保持停用前状态。

## 4. 店面与目录（A 域）

- **三域划分**：A 店面（售前公开）／B 工作台（登录后自研交易）／S 域（Shopify 托管，仅独立散买 Tier1 下单段）。订单查看一律回 B【订单】。
- **未登录零价格**：目录与 PDP 不显任何商品价（含 MSRP），占位"登录后可见批发价"。
  - **射程边界**：零价格只管**商品价格**（单品批发价／参考价／MSRP／整单报价结果）；**商业条款类数值未登录可见**（最低成交金额、起订量 MOQ、付款比例 30%/70%、报价有效期天数）。
- **PDP 按钮**：Tier1「加入购物车」／Tier2「进入配置器」＋FF&E「加入项目」（视觉分层）。
  - 交易 CTA 显隐＝按可售档位集合，不含则**不显**（非置灰）；「加入项目」不受档位过滤。
  - **不设 Tier3 入口**（呈现具体 SKU 的视图不得设；导航栏与购买流程页可设）。
- **档位选择器**（套餐行/自选行下拉）＝恒渲染，不可售置灰＋一行解释。
- **报价时效文案**：全站清理「即时/实时/自动/秒出」报价类表述，统一为「24 小时内提供正式报价」；清理范围＝所有对客触点（营销页/PDP/套餐页/配置器提交处/通知邮件模板）。
- **页面清单**：购买流程说明／住宅目录／工程目录三页纳入本文档管辖，定性＝既有站点复现，**纳管不纳建**——维持既有内容，仅在与口径冲突时修正。
- **价格用词统一**：废止「贸易价」「项目报价」。全站统一——**批发价**＝单品/行级 B2B 目录价（登录后可见，Catalog/Price List 承载）；**整单报价**＝项目/散单经报价流程产出的整单成交价（含人工校正、四眼发布）。
- **项目登记独家锁定＝不做**：不建项目归属/排他期/冲突检测/到期释放机制；项目登记入口归线索登记（飞书 Base），重复项目人工识别。已入废止清单，将来若做属新立项。
- **页脚联系块**：与四通道（电话/WhatsApp/邮件/联系表单）逐项对齐；此处表单＝联系表单（线索登记入口），非注册申请表单。
- **交付三件套对客措辞**（仅 Tier3 散单语境）：必须明示两级解锁时点——定金解锁 CAD 源文件＋无水印渲染图；尾款结清且 delivered 解锁 3D 模型＋完整包；不得表述为"下单即交付全套"。
- **整单最低成交金额＝US$5,000**：适用项目单（套餐立项＋自选组合立项同一门槛）；散单不适用金额门槛。**未登录可见**（属商业条款）。门槛为二选一结构，完整规则见 8.2。
- **门控文案统一为单一条件「登录」**：全站删除「登录并通过商户审核」并列句式（审核通过是登录的前置而非并列条件）。注册路径信息由引导注册卡片承载。

## 5. Tier1 现货

- **独立散买**：Shopify 标准 checkout，不落 FF-DB 状态机；只设数量门槛（最小数量/增量，Shopify quantity rules，值＝🟡⑭）；不设金额门槛；批发价不含运费税（运费税走 Shopify 设置）。
- **FF&E 容器内 Tier1 行**＝项目行记录：按批发价并入整单 Draft Order，**不走标准 checkout**（checkout 会被 quantity rules 拦下低于散买起订量的行）；DDP 口径；容器内 T1 行可低于散买起订量，对价＝整单金额门槛（见 8.2）。
- **数量门槛承载分工**：Shopify quantity rules 只承载 T1 散买门槛（需 checkout 层强制）；T2 生产 MOQ 不进 quantity rules（同一变体只能设一组值，散买起订量与生产 MOQ 是两个不同的数）。

## 6. Tier2 半定制

- **类型承载**：半定制类型＝Shopify SPU 参考变体（平铺枚举＋metafield 标身份与四维属性；禁"库存 0"判据；每类型带图＋人工预录参考价）。类型上架＝运营在 Shopify Admin 加变体，不找开发。
- **配置器**：三入口（PDP 预填/工作台直入/FF&E 行内调整）；选择框由枚举反推＋联动收敛（不存在的组合选不出来：置灰＋解释；选定即切类型图）；提交询价后端校验组合对应真实参考变体；未选全禁提交。
- **无确认价类型**：打标→不显参考价、仍可提交询价；进入询价队列时**内部标记「缺参考价」**，提示协调员优先补齐成本要素。
- **生产 MOQ**：粒度＝**按产品**（同产品不同配置的工厂起量相同）；校验位置＝自研侧 RFQ 提交环节（T2 不经 Shopify checkout）；存储位置归实施批。〔实施批须查证：Shopify quantity rules 为 catalog＋variant 级、每变体一组值，此为推理待验证〕
- **两阶段报价**：
  - 阶段一：Tier2/3 统一人工报价（参考价＋免责＋"24 小时内正式报价"文案，仅 Tier2）。
  - 分品类偏差达标亮灯→人工确认切自动（切自动＝参考变体放开可购、变体价即成交价；可随时切回）；参考价＋变体价格版本随询价单持久化；变体价变更样本清零。（阈值 N/±%＝🟡⑩）
- **Quote 四态**：pricing/quoted/expired/accepted。quoted 四出路＝接受/改配置（旧单 cancelled＋事由）/议价/放弃；pricing 期可自助放弃；重报多轮不设限、版本链留痕、superseded 四事由。
- **「24 小时」文案落点＝配置器提交处（全站唯一）**，PDP 与其他页不复示；仅适用散单 Tier2——**项目单对客不展示任何时限承诺**。无确认价类型同样承诺 24h（对客不区分有无参考价）。
- **状态映射**：以 NR-16 四态为准；Quote 态与 RFQ 态分表呈现、不合并编号；`accepted` 为 Quote 实体终态，对客文案落 14 态表的对客映射层。
- **定金态对客映射**：对客显示「待付首期」/「首期已付」（不再用"定金"字样）；收款单行紧随主单展示。**内部状态名仍为 `deposit_pending`/`deposit_paid`**（内部命名与对客文案分属两层）。

## 7. Tier3 全定制（RFQ）

- **一个 RFQ＝一个产品＋一个规格**（一副 CAD 一个尺寸）；多尺寸拆多 RFQ＋MOQ 人工核减通道；MOQ 按本 RFQ 数量软校验（低于可提交、显著标记、人工裁量）。
- **MOQ 粒度＝按品类**（品类主数据字段，值＝🟡①附）；校验仍按本 RFQ 数量执行。
- **客户端提交物**：
  - 部件级取材表（`部件|材料/型号|备注`，默认预填可改；可增行但材料必闭集）；
  - RFQ 级数量单框；
  - 模式①：CAD（白名单/限额/零解析；仅 submitted 前可删）；或模式②：参考图＋平面图＋现场尺寸。
  - 尺寸不由客户填；"规格行"由工程师 in_design 校正后产出。
- **状态机主路径（十态）**：submitted→in_design→design_review→pricing→quoted→deposit_pending→deposit_paid→in_production→delivered→closed。
  - 返工环多轮不设限；quoted 三出路；八态可自助取消；on_hold 三用途；可行性三层机制＋代改三防线；挂单治理（提醒天数＝🟡⑪）。
  - `revision_requested` 对客有独立文案（「修改中（已收到您的调整意见）」形态），不映射回 `in_design`。
  - **「放弃」落态＝`cancelled`＋事由「客户放弃」**，不新增 abandoned 态（单据级；项目容器语境见 8.3）。
- **设计资产解锁**：design_review 可看不可下（强水印＋预览版；历史轮次可点开）；deposit_paid 解锁 CAD 源＋无水印图；delivered＋尾款结清解锁 3D＋完整包（3D 格式＝🟡②）；三件套每单必交。
- **「确认收货」＝事件字段 `buyer_ack`，非状态**：不进状态机、不驱动流转；记录时点＋操作人；staff 推进 `closed` 时作参考输入展示，不作前置校验（`closed` 前置恒为「尾款结清＋三件套交付齐」）。

## 8. FF&E 项目

### 8.1 容器模型

- **容器＝T1 现货＋T2 半定制两档**；全定制一律独立散单 RFQ（商务侧人工协同门槛与排期）。
- 容器内任何行档位＝该产品可售档位 ∩{T1,T2}。SLA 统一 24h（对客不承诺）。
- **套餐**＝项目模板：**套餐预填量＝推荐默认值**（按房型配比预填，可增可减、不构成下限，减到 0＝删行）；Tier2 行必设默认配置；模板行校验 ∩{T1,T2} 非空。自组项目同受可售档位约束。

### 8.2 项目单成立条件与报价分流

- **成立三条件**（缺一不成立）：
  1. **≥2 类产品**——1 类产品＝散买，不走项目单；
  2. **T2 行 ≥ 生产 MOQ，全硬**——工厂要求，任何路径不放松；
  3. **整单金额二选一（析取）**：①所有行各自达标（T1 行 ≥ 散买起订量、T2 行 ≥ MOQ）→免金额门槛；或 ②整单总额 ≥ **US$5,000**。
  - 逻辑：金额门槛是「放松单品起订量」的对价——没享受放松就不付对价。项目单价值定位＝**用总额置换单品量**。
- **T1 行可低于散买起订量**（套餐路径与自选路径同规则），对价＝条件 3。
- **套餐发布校验＝立项校验（同一套规则）**：套餐在预填状态下必须通过成立三条件方可发布（区9，商务运营）；不另设更严规则。**参数变更重校验**：MOQ/散买起订量/金额门槛任一变更后，自动重扫已发布套餐，不合格者标记并通知商务运营处理。
- **删行规则**：删行自由、不设数量约束；全部约束收敛到**立项时校验成立三条件**这一个闸口；校验时机＝编辑过程实时软提示＋立项时硬校验。
- **报价分流**：
  - **全 T1 项目单→免报价**：系统自动建 Draft Order＋自动发 Payment Link，跳过报价编制与四眼复核（批发价即目录价，无人工核定内容）。
  - **含 T2 项目单→走整单报价**：协调员编制→四眼复核→商务运营发布；单一 Quote＋单一 Draft Order。
  - **技术约束（不可绕）**：全 T1 单必须走 Draft Order、不得走 Shopify 标准 checkout（checkout 层 quantity rules 会拦下低于散买起订量的行）。
- **满额阶梯折扣**：参数＝🟡⑮（基准与金额门槛联动）。
- **人工特批通道**：客户特殊要求（各行不达量且总额不足）→商务运营内部同意后可破例直接建 Draft Order 收款。四条件：①执行人＝商务运营；②强制附理由＋AuditLog；③按单核减、不改模板；④对客不明示。**特批单仍先生成项目单/Quote 记录再建 Draft Order**（保 1:N 对账与区8 清单不出孤儿单）。

### 8.3 容器行为与展示

- **来源标记 `src`**：缺省/非法一律落「自选组合」；`src`＝**立项来源**（不可篡改的溯源字段），客户后续增删行不改其值；自选项目后续加套餐＝允许，仍属同一项目（套餐内容作批量添加行并入），不另立项目。若需统计"内容含套餐成分"靠行级标记。
- **行级来源标记＝对客不展示**（纯内部：统计套餐渗透率／工程侧识别推荐配置）。
- **来源标记两层**：①FF&E 容器行级＝「我方预填/客户自选」；②取材表字段级＝「默认值/已改」（代改 BOM 三防线的判断依据）。工程师规格行不带标记（来源恒为工程师）。
- **容器行「放弃」语义**：容器行只有**删行**（无独立落态，触发整单 Quote `superseded` 第四事由「配置/行项变更重报」）；项目整体＝放弃项目（项目级 `cancelled`＋事由「客户放弃」）；八态自助取消仅适用散单与项目整体，不下沉到行级。
- **行级展示标签**＝「现货」「半定制」两枚（不用 Tier1/Tier2、不用标准品/配置品），与付款计划表述用词一致。
- **整单接受后的展示**：项目视图收敛为「订单摘要卡」（主单 `SO-`＋收款单 `SC-` 的单号/金额/状态三项），详情链去 B【订单】。分批发运对客展示归契约定稿批。**已知缺口**：MVP 阶段客户在项目视图只见整单级发运状态，不区分"现货已发/半定制在产"，契约定稿批必须补。
- **整单表述**：「已含金额（现货小计）＋半定制参考合计（单列不计入）」两行；报价单展开到规格行（工程师产出层）。
- **无确认价类型作 T2 行进容器**：①该行参考价列显「参考价未确认」（占位说明，不留空白）；②不计入半定制参考合计；③整单表述增提示「其中 N 项参考价待确认」。
- **套餐模板字段（区9）＝四字段**：①产品（SKU）必填；②套餐预填量必填（推荐默认值）；③默认配置（T2 行必填）；④行档位＝可售档位 ∩{T1,T2}（区9 只消费不维护可售档位集合）。保存校验＝T2 行默认配置必设＋档位交集非空；发布校验＝套餐预填状态通过立项校验。schema 随契约定稿批。
- **术语统一＝「套餐”**：废止「套包」，区9 名称＝「套餐管理面」。

## 9. 报价与定价

- **交易条款**：DDP 到门（Tier2/3 散单与整单）；仓储费条款制（超 14 天加收，费率＝🟡⑨）；报价单四要素（条款/有效期/交期/分行价）＋三条款家族（图纸责任/付款与解锁/变更与生产启动）；成本 markup 毛利零泄漏。
- **成本模型**：cost_breakdown 8 项（材料/工艺/五金/包装/头程/海外仓/尾程/关税）；主数据六表＋汇率（四眼维护、批量导入同走四眼、偏离表值强制附理由）；定价公式 5 段＋利润与 8 项两套切分正交；Shopify 运费模板＝调价杠杆，禁用于成本核算。
- **规则面**：切换开关／有效期默认（🟡⑧）／满额阶梯；参考价参数已退役。
- **单号体系**：前缀族 `SO-/SC-/PO-/Q-T2-/RFQ-/PRJ-/QT-`；Quote leaf「单号（类型）」后缀式；全实体编码细则（编号位数/年份/序列）归契约定稿批。
- **收款单模型**：主单 `SO-`＋收款单 `SC-`；三类收款（首期/尾款/补收）同用 `SC-` 前缀，靠 title 区分用途，格式「用途 · 关联 `SO-xxxx`」。
- **报价行颗粒度**：T1/T2 行＝一行一价、不展开（配置明细在项目行内点开）；单规格 Tier3＝一行直出、不建分组。「报价单展开到规格行」指工程师 in_design 产出的部件/工艺分解，与配置选项展开不是一回事。
- **区8「未核对」判定＝两类，非全集**：①webhook 已提示到账但未人工标记（优先显示，风险最高）；②已过应收时点仍未标记（催收对象）。未到应收时点的未标记单不进清单。置态权威仍为人工标记，webhook 仅作提示与预填。
- **邮件代录角色**：设计意见代录（区4）＝商务运营为主、客服可代录，AuditLog 记实际执行人；准入补件代传（区1）＝客服主责，不变。代录只替代"谁操作"不替代"谁复核"。

## 10. 生产、交付与订单展示

- **状态映射**：Order 生产十态对客六档映射（备产中/生产中/待发运/已发货/已交付/已完成）；细节态不透出。
- 物流手录三字段；ready_to_ship→shipped 前置＝尾款结清（人工标记）；closed＝staff 推进（尾款＋三件套）；确认收货＝非阻塞信号＋持久留痕。
- 订单列表 `SO-` 可下钻、`SC-`/`PO-` 不可下钻并注明缘由。
- **挂单超时不对客显示**：客户端只显「等待您确认」，不显"超时"或倒计时；催办走邮件提醒（天数＝🟡⑪）。报价有效期到期落 `expired` 必须对客显示（对客契约条款，与内部挂单治理分属两层）。
- **变更管理客户侧触发**：走四通道，不新建订单沟通区；订单详情页变更提示文案内置联系入口（「如需变更，请联系我们」＋四通道链接）。
