## 一、执行口径（R / A / W）

- **R｜结果**：每个问题必须形成“负责人现象 → 手册路径 → 最高事实源裁定 → 原型定位 → 修改 → 验证 → 负责人复验”的完整证据链。
- **A｜行动**：收到问题后分配 `W2-xxx` 编号；先核对矩阵，再按 `❌ 实现断链 / 🔍 事实源缺口 / ⚠️ 原型限制 / 📌 已知项` 分类；只有 `❌` 且事实源已有明确口径时直接改原型，`🔍` 不擅自补业务规则。
- **W｜触发时机**：负责人每报告一个业务链问题时立即登记；完成核查、修改、机器验证、负责人复验时分别更新同一条记录，不另起重复条目。

## 二、状态定义

| 状态 | 含义 | 下一步 |
|---|---|---|
| 待核查 | 已收到现象，尚未完成事实源核对 | 对照矩阵和手册定位 |
| 已核查待改 | 已确认属于实现断链 | 修改原型 |
| 待负责人裁决 | 矩阵缺口、冲突或业务取舍会改变结果 | 负责人拍板后再改 |
| 已修改待复验 | 已改原型并完成替代检查/机器验证 | 负责人沿原路径复验 |
| 已关闭 | 负责人复验通过，证据链完整 | 无 |
| 已知不处理 | 命中手册免重报项或明确的原型限制 | 记录依据，不改原型 |
