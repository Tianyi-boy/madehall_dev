## 4. 语义化规则

### 4.1 标签选择

| 内容 | 优先标签 | 说明 |
|---|---|---|
| 全局主导航、稿间切换 | `nav` | 带可访问名称，当前项使用 `aria-current` |
| 页面主体 | `main` | 每个 iframe 文档最多一个主要 `main` |
| 独立业务区域 | `section` | 用标题或 `aria-labelledby` 建立名称 |
| 可独立理解的实体卡 | `article` | 产品、RFQ、Quote、Order、项目等 |
| 提交型输入区 | `form` | 有明确提交动作和校验边界 |
| 同组字段 | `fieldset`＋`legend` | 配置器、筛选、权限选择等 |
| 行列事实 | `table` | 表头使用 `th` 和正确 `scope` |
| 弹层 | `dialog` 或等价可访问结构 | 明确标题、关闭和焦点返回 |
| 状态提示 | `output`、`status`/`alert` 角色 | 区分普通结果与错误 |
| 纯布局或装饰 | `div`、`span` | 不制造无意义语义层级 |

### 4.2 稳定锚点

命名约定：

- 外壳：`shell.*`
- A 店面：`a.*`
- B 客户工作台：`b.*`
- C 内部后台：`c.*`
- 使用业务含义，不使用数组序号、样式名或易变中文文案作为测试 ID。
- 同一 iframe 文档内 `data-testid` 必须唯一；跨 iframe 也优先保持前缀唯一。
- 实体承载点增加 `data-entity-type` 和 `data-entity-id`；当前状态可使用 `data-state`。
- 不把实体 ID 硬编码成测试 ID，例如使用 `b.quote.detail`，实体号另放 `data-entity-id="QT-1007-01"`。

### 4.3 12 条流程 ID

| 路径 | `data-flow` |
|---|---|
| 商户准入 | `FLOW-01-MERCHANT-ONBOARDING` |
| Tier1 | `FLOW-02-TIER1` |
| Tier2 | `FLOW-03-TIER2` |
| Tier3 | `FLOW-04-TIER3` |
| FF&E 套餐项目 | `FLOW-05-FFE-PACKAGE` |
| FF&E 自组项目 | `FLOW-06-FFE-CUSTOM` |
| 单号与路由 | `FLOW-07-ROUTING` |
| 角色权限 | `FLOW-08-RBAC` |
| 主数据治理 | `FLOW-09-MASTER-DATA` |
| AuditLog | `FLOW-10-AUDIT` |
| 客服与例外 | `FLOW-11-SUPPORT-EXCEPTION` |
| 跨稿总检 | `FLOW-12-CROSS-VIEW` |

一个元素可以属于多个流程；值使用空格分隔。流程锚点必须落在真实入口、关键中间态和完成/回链位置，不能只集中写在页面根节点。

### 4.4 规则注释

推荐格式：

```html
<!--
  @flow FLOW-03-TIER2
  @source 00-v4.10/W8-01
  @entity QuoteRequest
  @future-contract QuoteRequest.Create
  @rule 参考变体必须属于当前产品且组合真实存在
  @error INVALID_REFERENCE_VARIANT
-->
```

约束：

- 注释放在对应 DOM 或处理逻辑附近，不建立远离实现的大段注释墙。
- 记录规则来源和“为什么”，不复制整段需求正文。
- API 名称只能标为 `@future-contract`，本阶段不虚构真实端点已经存在。
- 注释必须与当前有效口径一致，停用规则不得重新写入。
